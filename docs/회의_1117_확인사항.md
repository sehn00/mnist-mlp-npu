# 11/17(화) 통합 회의 확인 사항 (조원4 정리, 2026-11-14, 출력 레지스터 OFF 결과로 갱신)

근거: Vivado 2024.2 결과 (`README.md` 결과 요약, `reports/`). 번호는 README 4절 불일치 목록 번호.
**과제 공식 가이드(`docs/AISSD_project_과제설명및요구사항.pdf`)가 팀 스펙보다 우선.** 가이드 대조표: `docs/과제가이드_요구사항_체크.md`

## 먼저 보여줄 것
- **가이드 p.9 규칙("Primitives Output Register should be disabled")에 맞춰 BRAM 출력 레지스터를 전부 끈 구성(읽기 지연 1클럭, RD_LAT=1)으로 다시 검증함.** 11/12 B IP(WMEM·BMEM ON) 구성은 이 규칙 위반
- A+B+C+D 통합이 Vivado 실제 BRAM IP로 **사진 100장 전부 golden v2와 비트 일치, 예측 100/100**, 장당 119,009클럭, 시뮬레이터 경고 0개
- 합성 + 구현 완료, **100MHz 충족 (WNS +2.553 ns, WHS +0.054 ns)**, BRAM 112/144 타일, LUT 1,185, FF 283, DSP 0, 전력 0.367 W (동적 0.077 + 정적 0.289)
- A·B·C 원본 파일은 한 줄도 안 고쳤음. B는 임시 어댑터(`rtl/npu_mem_ctrl.v`)로 감쌌고, BRAM IP는 내 스크립트(`run_sim.tcl`)가 출력 레지스터 OFF로 새로 만듦
- 이전 ON 구성 결과(장당 119,659클럭, WNS +2.138 ns)는 비교용으로 `reports/archive_oreg_on/`에 보관

## 조원2 (B 메모리)
1. **읽기 지연 (#1)**: 가이드 p.9 규칙상 **WMEM(wmem_bank0~3)·BMEM(bmem_128)을 Primitives Output Register OFF로 재생성 필요** (지금 .xci는 ON, 읽기 지연 2). D·어댑터·top은 RD_LAT=1로 반영이 끝났고, OFF 구성으로 100장 일치 + 타이밍 충족을 확인함. 같이 고칠 것: `memory_controller.v` 214·216줄의 weight_valid/bias_valid가 req를 2클럭 늦춘 값 → OFF에서는 1클럭 지연이 맞음 (통합에서는 이 valid를 안 써서 결과는 같음)
   - (11/15 외부 검수 D06) 위 valid는 req를 2단 지연해서 OFF IP 데이터보다 1클럭 늦음 (OFF: 첫 데이터 req+1, valid req+2). 최종 인터페이스에서 valid를 실제 IP 지연에 맞추거나, 안 쓰는 출력이면 정리. ena를 req로 게이트하게 바꾸면 BMEM 선행 읽기·RD_LAT=2 파이프라인까지 다시 검증 필요. 근거: `docs/review_codex_1115.md` D06
2. **WMEM 구조 (#2)**: 11/10 카톡은 "32bit × 117,056" 단일, 11/12 zip은 4뱅크. 4뱅크가 최종 맞는지
3. **정식 npu_mem_ctrl (#3, #4)**: 외부 인터페이스 + busy MUX + 읽기 MUX를 누가 마무리할지. 내 어댑터를 그대로 정식으로 써도 되는지, 주소 맵(`i_addr[19:17]`: 2 IMEM_A, 3 ACT_A, 4 ACT_B, 5 OMEM)과 모듈/포트 이름(memory_controller, clk/rst)
   - (11/15 외부 검수 D02) **지금 어댑터 주소 맵은 스펙 v0.2 §3과 안 맞음**: v0.2는 번호 0/1 = WMEM/BIAS 쓰기, 4 = OMEM. 어댑터는 0/1 = 쓰기 무시·읽기 0, 2/3/4/5 = IMEM_A/ACT_A/ACT_B/OMEM → v0.2대로 4번에서 결과를 읽으면 ACT_B가 읽힘. 최종 주소·깊이·읽기/쓰기 권한을 정해서 스펙과 TB에 같이 반영. 근거: `docs/review_codex_1115.md` D02
4. **가중치 넣는 방법 (#4)**: WMEM·BMEM이 COE 초기화 전용(wea=0)이라 외부 포트로는 가중치를 못 씀. 가이드 p.3은 제출물에 "testbench and hex file for data import"를 요구함 → **가중치를 테스트벤치가 hex로 써 넣는 구조가 필요한지, COE 초기화로 괜찮은지** (교수님 확인 필요. 필요하면 B의 wea 고정을 풀고 어댑터 주소 맵에 WMEM/BMEM 쓰기를 추가해야 함)
   - (11/15 외부 검수 D02) 호스트 적재가 필요하다고 정해지면 WMEM은 4뱅크, BMEM은 128b 라인 단위로 쓰는 경로를 새로 만들어야 함 (지금은 COE 초기화만, `wea=0`)
5. **IMEM_B (#9)**: 아무도 안 써서 구현 때 지워짐. 더블 버퍼를 쓸 계획인지
6. **ena 고정 (#10)**: WMEM·BMEM ena가 1'b1. D 쪽에서 주소 범위를 맞춰 놨으니 동작은 문제없음. 가이드 p.12는 ena = ~CEN 형태로 연결하라고 함 → req에 연결할지
7. **Vivado 강제 종료 (#8)**: 합성이 죽던 문제. 병렬 작업 수를 줄이면(`launch_runs -jobs 2`) 되는지 확인 부탁. 내 PC(RAM 16GB)에서는 8개로 돌렸을 때 IP 런 3개가 죽었고 2개로 해결됨
8. BRAM 사용량 112/144 타일 (77.8%), BRAM 동적 전력 0.038 W. 보고서 8번(구현 결과)용 숫자

## 조원3 (C PE 배열, 스펙·이름 규칙)
1. **C 최종본 (#6)**: C_pe_array_final.zip(clk/rstn)과 handoff_D/rtl(i_clk/i_rstn) 중 handoff 버전을 썼음. 이게 최종 맞는지
2. **DSP 0개 (#11)**: 곱셈 4개가 LUT로 합성됨 (C 블록 LUT 154, FF 97). 의도한 건지, DSP로 강제할지. 타이밍은 지금도 충족. 참고: 출력 레지스터를 끄면서 가장 느린 경로가 WMEM 출력 → C 곱셈 → 곱 레지스터(7.09 ns, 여유 2.55 ns)로 바뀜
3. **이름 규칙 표 (#7)**: D 포트 `o_rd_en`, `o_wbank_addr`, `o_wbank_sel` 추가
   - (11/15 외부 검수 D08) 이름 규칙 PDF와 최종 구성이 다른 곳: B 하위 래퍼 `clk/rst`(동기 active-high, 어댑터가 변환), C 내부 레지스터에 `r_` 접두사 없음, 규칙 §3의 `waddr` 대신 B에는 뱅크 주소/선택(`o_wbank_addr`/`o_wbank_sel`)과 `o_rd_en`이 연결됨 (폭은 일치). **제출 이름 규칙을 하위 모듈까지 엄격히 적용할지** 정하고, 최종 B 계층·4뱅크 포트를 팀 연결 표에 반영. 근거: `docs/review_codex_1115.md` D08
4. **스펙 갱신 (#5)**: v0.2의 메모리 맵(ACT_A 228줄 등), shift 10/9 → 11/7, RD_LAT=1(가이드 규칙), 4뱅크 반영해서 v1.0
   - (11/15 추가, 외부 재검수) **v0.2 §6-2/§6-5 DONE 상태표 정정 필요**: 지금 표는 "DONE 상태 클럭에 o_done = 1"인데, 11/15 D01 수정 후 D는 **DONE을 끝내는 엣지(IDLE로 가는 엣지)에 o_done = 1과 o_busy = 0을 같이** 바꿈. 이 엣지에 OMEM 9번 마지막 쓰기도 끝남. 그래서 §6-1의 "o_done = 1 기다리기 → 읽기" 순서가 그대로 동작하고, 그 다음 상승 엣지부터 외부 읽기와 i_start가 받아들여짐. 연산 길이(start 수락 엣지 → done 엣지)는 119,009클럭 그대로. 근거: `docs/review_codex_1115.md` 재검수 절, `rtl/npu_ctrl.v` S_DONE
5. 11/19 목표(100장 정확도, 합성·타이밍)가 이미 됐으니 남은 일정에 무엇을 할지 (보고서 캡처? 보드 동작? #13)

## 조원1 (A 후처리, golden)
1. A 원본 그대로 통합해서 shift 11/7로 100장 비트 일치. A 쪽 수정 요청 없음
2. **golden 정확도**: 11/10에 "99.30%, 다시 확인 후 정정"이라고 했던 값의 최종 숫자
3. **테스트셋 정확도를 몇 장으로 할지 (#14)**: 가이드 보고서 6번이 "MNIST Test dataset hardware execution results (test accuracy)". 통합 TB는 100장만 봄 (100/100), golden hex도 100장분만 있음. 더 보려면 golden hex 추가 필요
4. **golden 파일 이름**: `fc1_out_act_b.hex`가 지금 구성에서는 ACT_A에, `fc2_out_act_a196.hex`는 ACT_B에 들어감. 이름을 메모리 흐름(FC1 → ACT_A, FC2 → ACT_B)에 맞게 바꿀지
5. **(11/15 외부 검수 V04) golden 재생성 기본값**: `golden_v1.py`의 `--select` 기본값이 `test`라, 인자를 빼고 돌리면 테스트셋으로 shift 289개 조합을 고르고 같은 테스트셋으로 최종 정확도를 잼 (v2 산출물과 README 재현 명령은 `train`). 기본값을 `train`으로 바꾸거나 필수 인자로 만들고, 산출물에 보정 데이터와 shift를 기록할지. 근거: `docs/review_codex_1115.md` V04

- 보고서 캡처 분담 (가이드 p.13): 블록도(학생별 IP 상세는 따로 제출), 파형 4장(SRAM 읽기/쓰기, 연산 시작/끝), 구현 후 schematic(전체 + IP별), Device 화면, 자원·타이밍·전력. 보고서 템플릿은 e-class에서 받아야 함
- 내 폴더 공유 방법: zip으로 올릴지 (rtl 6개 + tb 2개 + constr + run_sim.tcl + run_impl.tcl + README)
