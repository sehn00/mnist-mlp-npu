# 11/17(화) 통합 회의 확인 사항 (조원4 정리, 2026-11-14)

근거: Vivado 2024.2 결과 (`README.md` 결과 요약, `reports/`). 번호는 README 4절 불일치 목록 번호.

## 먼저 보여줄 것
- A+B+C+D 통합이 Vivado 실제 BRAM IP로 **사진 100장 전부 golden v2와 비트 일치, 예측 100/100**
- 합성 + 구현 완료, **100MHz 충족 (WNS +2.138 ns, WHS +0.041 ns)**, BRAM 112/144 타일, LUT 1,199, FF 341, DSP 0
- A·B·C 원본 파일은 한 줄도 안 고쳤음. B는 임시 어댑터(`rtl/npu_mem_ctrl.v`)로 감쌌음

## 조원2 (B 메모리)
1. **읽기 지연 (#1)**: WMEM·BMEM 출력 레지스터 ON(지연 2)을 최종으로 할지. 지금 구성(ON, RD_LAT=2)으로 100장 일치 + 타이밍 충족을 확인했으니 그대로 가는 쪽을 제안. OFF는 안 돌려봤음
2. **WMEM 구조 (#2)**: 11/10 카톡은 "32bit × 117,056" 단일, 11/12 zip은 4뱅크. 4뱅크가 최종 맞는지
3. **정식 npu_mem_ctrl (#3, #4)**: 외부 인터페이스 + busy MUX + 읽기 MUX를 누가 마무리할지. 내 어댑터를 그대로 정식으로 써도 되는지, 주소 맵(`i_addr[19:17]`: 2 IMEM_A, 3 ACT_A, 4 ACT_B, 5 OMEM)과 모듈/포트 이름(memory_controller, clk/rst)
4. **가중치 넣는 방법 (#4)**: WMEM·BMEM이 COE 초기화 전용(wea=0)이라 외부 포트로는 가중치를 못 씀. 이대로 가도 되는지
5. **IMEM_B (#9)**: 아무도 안 써서 구현 때 지워짐. 더블 버퍼를 쓸 계획인지
6. **ena 고정 (#10)**: WMEM·BMEM ena가 1'b1. D 쪽에서 주소 범위를 맞춰 놨으니 동작은 문제없음. req에 연결할지는 선택
7. **Vivado 강제 종료 (#8)**: 합성이 죽던 문제. 병렬 작업 수를 줄이면(`launch_runs -jobs 2`) 되는지 확인 부탁. 내 PC(RAM 16GB)에서는 8개로 돌렸을 때 IP 런 3개가 죽었고 2개로 해결됨
8. BRAM 사용량 112/144 타일 (77.8%). 발표 자료용 숫자

## 조원3 (C PE 배열, 스펙·이름 규칙)
1. **C 최종본 (#6)**: C_pe_array_final.zip(clk/rstn)과 handoff_D/rtl(i_clk/i_rstn) 중 handoff 버전을 썼음. 이게 최종 맞는지
2. **DSP 0개 (#11)**: 곱셈 4개가 LUT로 합성됨 (C 블록 LUT 154, FF 97). 의도한 건지, DSP로 강제할지. 타이밍은 지금도 충족
3. **이름 규칙 표 (#7)**: D 포트 `o_rd_en`, `o_wbank_addr`, `o_wbank_sel` 추가
4. **스펙 갱신 (#5)**: v0.2의 메모리 맵(ACT_A 228줄 등), shift 10/9 → 11/7, RD_LAT, 4뱅크 반영해서 v1.0
5. 11/19 목표(100장 정확도, 합성·타이밍)가 이미 됐으니 남은 일정에 무엇을 할지 (보드 동작? #13)

## 조원1 (A 후처리, golden)
1. A 원본 그대로 통합해서 shift 11/7로 100장 비트 일치. A 쪽 수정 요청 없음
2. **golden 정확도**: 11/10에 "99.30%, 다시 확인 후 정정"이라고 했던 값의 최종 숫자. 통합 TB는 100장만 봄 (100/100)
3. **golden 파일 이름**: `fc1_out_act_b.hex`가 지금 구성에서는 ACT_A에, `fc2_out_act_a196.hex`는 ACT_B에 들어감. 이름을 메모리 흐름(FC1 → ACT_A, FC2 → ACT_B)에 맞게 바꿀지
4. 100장보다 많은 사진으로 정확도를 볼 건지 (golden hex 추가 필요)
